Benchmark this stack (k6)

Stack hiện đang chạy với ~2 GB RAM / 2 CPU cap (xem docker-compose.yml). Các kịch bản dưới đã tune cho hardware đó — tránh fire 5000 VUs đồng thời, dùng constant-arrival-rate để giữ ổn định. Copy lệnh và chạy trong terminal. 

# 1) Smoke (30s, 5 VUs) — gate trước stress run
k6 run test-data/k6-smoke.js

# 2) Light load — 1000 orders, ~50 req/s, ~20s
k6 run -e TARGET_ORDERS=1000 -e RATE=50 test-data/k6-benchmark.js

# 3) Medium — 2500 orders, ~80 req/s, ~30s
k6 run -e TARGET_ORDERS=2500 -e RATE=80 test-data/k6-benchmark.js

# 4) Heavy for homelab — 5000 orders, ~80 req/s, ~60s
k6 run -e TARGET_ORDERS=5000 -e RATE=80 test-data/k6-benchmark.js

# 5) So sánh REDIS vs DATABASE engine (chạy 2 lần, đổi mode giữa chừng)
curl -X POST http://localhost:8083/admin/stock-engine/DATABASE
k6 run -e TARGET_ORDERS=1000 -e RATE=50 test-data/k6-benchmark.js
curl -X POST http://localhost:8083/admin/stock-engine/REDIS
k6 run -e TARGET_ORDERS=1000 -e RATE=50 test-data/k6-benchmark.js

Sau khi chạy, mở / để xem tổng số order, hoặc Kafdrop :9000 để inspect message lưu lượng. Nếu CPU container vượt 80% (xem docker stats) thì giảm RATE xuống.
